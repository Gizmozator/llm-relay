# llm-relay — v1 Plan

**Date:** 2026-11-20
**Status:** v1 implemented and deployed (local compose verified; prod-host stack ready via Dockge)
**One-liner:** OpenAI-compatible proxy that fronts local LLMs, meters token usage per API key and client IP, prices it, and shows cost dashboards — all in one Go binary + SQLite, in Docker.

## 1. Goal & use case

Share a local LLM (currently the halogen engine, OpenAI-compatible API) with friends over a public endpoint. Every friend gets their own API key; the proxy logs every request's token usage and computes cost from admin-configured prices (input / output / cache-read). A web dashboard shows usage and cost per key, per client IP, per day, per model.

## 2. Decisions (from planning Q&A)

| Topic | Decision |
|---|---|
| Key management | Users create their own API keys in the dashboard after login |
| Accounts | JWT auth, two roles: **admin** (manages users, backends, model catalog, prices) and **user** (manages own keys, sees own usage) |
| Backend discovery | Admin adds an **LLM backend** (base URL + optional key); the app probes its `/v1/models` and `/health`, and the admin **picks which discovered models enter the catalog** — no hand-typed URLs per model |
| Limits | **None in v1** — pure logging. Rate limits/budgets deferred (schema leaves room) |
| Streaming | Full SSE pass-through; usage counted from the final upstream `usage` chunk, heuristic fallback otherwise |
| Usage view | Token counts **and** cost, grouped by key and day (plus IP, model and **session** breakdowns) |
| Sessions | Usage rows carry a `session_id`: explicit `X-Session-Id` header wins, else a stable hash of (key, model, first user message) groups a conversation's requests automatically |
| Deployment | Runs on **prod-host** via **Dockge** compose; image published to the **Gitea container registry** (`gitea.rantaeskola.fi/gizmoz/llm-relay`) |
| Currency | **One currency per install, admin-configured** in Settings (default EUR), no conversions; prices and costs always in it |
| Storage | SQLite3, single file on a Docker volume |
| Deployment | Docker, single container (Go binary + embedded dashboard) |
| Upstream protocols | Proxy speaks **four dialects** the halogen engine serves: OpenAI chat/completions, OpenAI completions, OpenAI Responses API (Codex CLI), Anthropic Messages API (Claude Code) — plus NPU sidecar routes (embeddings etc.). See §7 |

## 3. Architecture

```
friend's app ──(Bearer sk-...)──▶ ┌─────────────────────────────┐
                                  │  ai-proxy (Go, :8080)       │
dashboard ──(JWT)──▶ /api/* ────▶ │  ┌────────┐  ┌───────────┐  │──▶ upstream LLM #1 (llama.cpp/halogen)
        (static SPA from embed)   │  │ proxy  │─▶│ forwarder │  │──▶ upstream LLM #2
                                  │  └───┬────┘  └───────────┘  │──▶ upstream LLM #N
                                  │      ▼                      │
                                  │  usage recorder → SQLite    │
                                  └─────────────────────────────┘
```

Single binary, three concerns:
1. **Proxy** (`/v1/*`) — authenticates `sk-` keys, routes by requested model to its backend's base URL, streams through, records usage.
2. **JSON API** (`/api/*`) — JWT-authenticated: login, key CRUD, usage queries, admin management.
3. **Dashboard** — static SPA embedded with `go:embed`, served by the same binary.

## 4. Tech stack

| Concern | Choice | Why |
|---|---|---|
| Language | Go 1.23+ | as requested; stdlib `net/http` with 1.22+ route patterns — no web framework |
| SQLite driver | `modernc.org/sqlite` | pure Go, no cgo → trivial static build, alpine/distroless friendly |
| Migrations | embedded SQL files + `schema_version` table, run at startup | no extra tooling |
| JWT | `github.com/golang-jwt/jwt/v5` | standard |
| Passwords | `golang.org/x/crypto/bcrypt` | standard |
| SSE | hand-rolled line reader on upstream body + `http.Flusher` | small, no dependency |
| Frontend | Vite + React + Chart.js, embedded via `go:embed` | small SPA, talks to `/api/*`; charts for the cost timeline |
| Config | env vars only (parsed with `caarlos0/env`) | Docker-native |

Money math: prices stored and computed in **integer micro-units** (1e-6 currency units) per 1M tokens to avoid float drift. Display divides back.

## 5. Data model (SQLite, WAL mode)

```sql
users (
  id INTEGER PK, username TEXT UNIQUE, pass_hash TEXT,
  role TEXT CHECK(role IN ('admin','user')),
  disabled INTEGER DEFAULT 0, created_at TEXT
);

api_keys (
  id INTEGER PK, user_id INTEGER REFERENCES users,
  name TEXT,                       -- "laptop", "friend-jussi-phone"
  key_hash TEXT UNIQUE,            -- SHA-256 of the full key; plaintext shown once at creation
  key_prefix TEXT,                 -- first 8 chars, for display only
  created_at TEXT, revoked_at TEXT NULL, last_used_at TEXT NULL
);

backends (                          -- LLM servers the admin has connected
  id INTEGER PK,
  name TEXT UNIQUE,                -- "halogen (iGPU)", "npu-sidecar"
  base_url TEXT,                   -- e.g. http://gitea-host:8731 (no path)
  api_key TEXT NULL,               -- upstream auth, if the backend requires one
  enabled INTEGER DEFAULT 1,
  last_probe_at TEXT NULL,         -- last /v1/models + /health probe result
  last_probe_error TEXT NULL,      -- NULL = reachable; else last failure message
  server_version TEXT NULL,        -- from /health, display only
  created_at TEXT
);

models (                            -- public catalog, rows created from discovery
  id INTEGER PK,
  backend_id INTEGER REFERENCES backends,
  upstream_model TEXT,             -- model id exactly as the backend's /v1/models reported it
  name TEXT UNIQUE,                -- public name clients request; defaults to upstream_model, editable
  enabled INTEGER DEFAULT 1,
  price_in INTEGER,                -- micro-units per 1M prompt tokens
  price_out INTEGER,               -- micro-units per 1M completion tokens
  price_cache_read INTEGER,        -- micro-units per 1M cached prompt tokens
  price_cache_write INTEGER DEFAULT 0, -- micro-units per 1M cache-creation tokens (Anthropic dialect); 0 = free/unused
  UNIQUE(backend_id, upstream_model)
);

settings (                          -- single-row-ish key/value, admin-editable
  key TEXT PK, value TEXT
);                                  -- v1 keys: 'currency' (ISO code, default 'EUR')

usage (
  id INTEGER PK, ts TEXT,
  user_id INTEGER, api_key_id INTEGER,
  client_ip TEXT,                  -- X-Forwarded-For first hop, else conn IP
  session_id TEXT,                 -- X-Session-Id header, or derived conversation hash
  endpoint TEXT,                   -- 'chat' | 'completions' | 'responses' | 'messages' | 'embeddings'
  model_id INTEGER, model_requested TEXT, model_upstream TEXT,
  prompt_tokens INTEGER, completion_tokens INTEGER,
  cached_tokens INTEGER, cache_write_tokens INTEGER,
  cost_in INTEGER, cost_out INTEGER, cost_cache INTEGER, cost_total INTEGER,
  streamed INTEGER, usage_estimated INTEGER,  -- 1 if heuristic fallback was used
  status_code INTEGER, latency_ms INTEGER, error TEXT NULL
);
-- indexes: usage(ts), usage(api_key_id, ts), usage(user_id, ts)
```

Cost is **computed and stored at request time** — changing a price later never rewrites history. `cost_*` columns are the snapshot. There is **one currency per install**, chosen by the admin in Settings (`settings.currency`); prices and costs are always in it, **no conversions anywhere**.

## 6. API surface

### Proxy (auth: `Authorization: Bearer sk-...`)
| Route | Dialect | Behavior |
|---|---|---|
| `POST /v1/chat/completions` | OpenAI chat | main path; `stream: true`, tools, `response_format` pass through untouched |
| `POST /v1/completions` | OpenAI text | raw-prompt route, same accounting |
| `POST /v1/responses` | OpenAI Responses | Codex CLI drives this; **stateless upstream** (no response store) so plain forwarding is safe — history arrives with every request |
| `POST /v1/messages` | Anthropic | Claude Code drives this; pass `anthropic-version` / `x-api-key` handling through |
| `POST /v1/messages/count_tokens` | Anthropic | pure pass-through, **no usage row** (no generation happens) |
| `POST /v1/embeddings` | OpenAI (NPU sidecar) | prompt-token-only accounting (`completion_tokens = 0`) |
| `GET /v1/models` | — | lists enabled catalog models (public names only) |

Anything else under `/v1/*` (rerank, moderations, images, audio, `/classify`, `/v1/systemone`) is **not proxied in v1** — 404 with an OpenAI-style error; the catalog + dialect table makes adding one later a small change.

Unknown model name → `404` OpenAI-style error. Revoked/unknown key → `401`. Requests are recorded even on upstream errors (with `status_code`/`error`), so failures are visible too.

### Dashboard API (auth: JWT)
| Route | Role | Notes |
|---|---|---|
| `POST /api/auth/login` | — | username+password → access token (12 h) |
| `GET /api/me` | user | profile + role |
| `GET/POST/DELETE /api/keys` | user | list / create (returns plaintext once) / revoke |
| `GET /api/usage/summary?from&to&group_by=key\|day\|model\|ip\|endpoint` | user | own usage totals + cost |
| `GET /api/usage/detail?from&to&page` | user | per-request rows |
| `GET /api/admin/users` (+POST/PATCH) | admin | create user, set password, disable |
| `GET /api/admin/backends` (+POST/PATCH/DELETE) | admin | manage backends; POST only stores + probes, it never auto-adds models |
| `POST /api/admin/backends/{id}/probe` | admin | re-probe; returns discovered model ids with `in_catalog` flag + `/health` version — powers "Sync models" |
| `POST /api/admin/backends/{id}/models` | admin | bulk-add selected discovered models to the catalog (public name defaults to upstream id) |
| `GET /api/admin/models` (+PATCH/DELETE) | admin | edit public name / prices, enable/disable, remove from catalog |
| `GET /api/admin/usage/summary?...` | admin | everything, filterable by user/key |
| `GET/PUT /api/admin/settings` | admin | install settings; v1 content is just `currency` (ISO 4217 code, free-text, no conversion) |

### Auth & security
- First run: if no users exist and `ADMIN_USERNAME`/`ADMIN_PASSWORD` env are set, bootstrap an admin account.
- JWT signed with `JWT_SECRET` (required env), HS256, 12 h expiry, sent as `Authorization: Bearer` from the SPA (no cookies → no CSRF surface).
- API keys: `sk-` + 32 random hex; only the SHA-256 hash is stored; brute-force-friendly lookup is fine at this scale (indexed unique lookup on hash).
- Client IP: trust `X-Forwarded-For` only when `TRUST_PROXY_HEADERS=1` (running behind the homelab reverse proxy).
- TLS termination is the reverse proxy's job; the container listens plain HTTP.

## 7. Proxy request flow & upstream dialects

The halogen engine serves all four dialects on **one port** (`:8731`). A model belongs to a **backend** (base URL + optional key); the proxy forwards to the **same path** on the backend's base URL. NPU-sidecar routes (embeddings) point at the sidecar's backend row instead.

0. **Dialect usage extraction** — each dialect reports tokens differently; one extractor per dialect, feeding the same `usage` row:

| Dialect | Non-streaming usage source | Streaming usage source | Mapping to our columns |
|---|---|---|---|
| OpenAI chat/completions | `usage.{prompt_tokens, completion_tokens, prompt_tokens_details.cached_tokens}` | final SSE chunk with `usage` (we force `stream_options.include_usage = true`) | prompt / completion / cached |
| OpenAI Responses | `response.usage.{input_tokens, output_tokens, input_tokens_details.cached_tokens}` | `response.completed` SSE event carries the same object | input→prompt, output→completion |
| Anthropic messages | `usage.{input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens}` | `message_start` event (input + cache numbers) **and** `message_delta` event (final `output_tokens`) — capture both | input→prompt, output→completion, cache_read→cached, cache_creation→cache_write |
| Embeddings | `usage.prompt_tokens` | n/a | prompt only |

Note: only the Anthropic dialect reports cache-**write** (cache creation) tokens; `price_cache_write` defaults to 0 elsewhere. The engine also returns a llama-server-style `timings` object (`prompt_n`, `predicted_n`, `cache_n`) on every response — we log `latency_ms` ourselves and ignore `timings` in v1 (candidate for later analytics).

Flow:

1. Parse bearer key → hash → look up `api_keys` (not revoked) → resolve user.
2. Peek at request body's `model` field (decode into a struct, keep raw body for forwarding) → resolve enabled catalog model (and its backend) → 404 if unknown/disabled.
3. Rewrite `model` to `upstream_model` — the public name and the backend's reported id can differ, and Codex CLI / Claude Code send their own names (e.g. `gpt-5-codex`, `claude-sonnet-4-5`) that must map onto `halogen-qwen3.8-flash-next`. Inject the backend's auth if set (Bearer for OpenAI dialects, `x-api-key` for Anthropic).
4. **Non-streaming:** forward, read response, run the dialect's extractor.
5. **Streaming:** SSE pass-through with flush-per-chunk (the engine's keepalives pass through too — never buffer). While copying, scan for the dialect's usage carrier (table above). If none arrives, estimate: `completion_tokens ≈ words + chars/4 heuristic`, `prompt_tokens ≈ chars/4`, mark `usage_estimated = 1`.
6. Compute cost snapshot, insert `usage` row, update `last_used_at`. Insert happens **after** the response completes (streaming) — use a buffered write (single-goroutine writer channel) so request handling never blocks on SQLite.
7. **Client hang-ups are recorded too:** if the client disconnects mid-request (engine logs these as 499), record the row with `status_code = 499` and whatever usage is known (estimated for partial streams). Upstream errors likewise get a row with the error status.

SQLite concurrency: WAL mode, `busy_timeout=5000`, single writer via the buffered writer goroutine → no `SQLITE_BUSY` under normal load.

### Backend discovery & probing

When the admin adds a backend (name + base URL + optional key), and whenever they hit **Sync**, the app probes it:

1. `GET {base}/health` — reachability + version. halogen keeps `/health` open even when an API key is required, so this works before credentials are known; for non-halogen backends a 401 here still counts as "reachable".
2. `GET {base}/v1/models` (with the backend key if set) — the model id list.
3. The probe result is stored on the backend row (`last_probe_at`, `last_probe_error`, `server_version`) and shown live in the admin UI: green/red status per backend.
4. The discovered list is diffed against the catalog: **new** models get checkboxes (pre-checked, admin unchecks what they don't want to publish), **existing** ones are marked, models in the catalog whose upstream id **vanished** are flagged so the admin can retire them. Nothing is auto-added or auto-removed — discovery proposes, admin decides.
5. Prices start at 0 for newly added models; the proxy serves them fine, they just show as free until priced.

## 10. Docker & deployment

- Multi-stage `Dockerfile`: `node` stage builds the SPA → `golang` stage builds static binary (CGO off) → `scratch` final image; `go:embed` carries the SPA.
- **Image registry**: `make docker-release VERSION=x.y.z` builds `linux/amd64`, tags and pushes to the Gitea container registry: `gitea.rantaeskola.fi/gizmoz/llm-relay:<version>` (+ `:latest`). `docker login gitea.rantaeskola.fi` with a `write:package` token is a one-time host setup.
- **Target host: prod-host (prod-host)**, managed by the user through **Dockge**. `deploy/dockge-compose.yml` is the stack file to paste into Dockge: registry image, bind-mount data dir `/docker/llm-relay/data:/data` (prod-host rule: persistent data under `/docker/<container>/`), env via the stack's `.env` (`JWT_SECRET`, bootstrap admin, `TZ`), published port via `PORT`.
- Upstream LLMs live on the LAN → backend base URLs point at LAN addresses (halogen = `http://engine-host:8731`; it binds `*:8731` via the rootless port mapping, so prod-host reaches it).
- Local dev/testing stays on this box with `make docker-up` (compose file at repo root, named volume).

### 2026-11-20 — SSE keepalive for edge proxies

- Streams now inject an SSE comment (`: keepalive`) after 20 s of upstream
  silence. Motivation: external clients (a friend, off-LAN) reach the relay
  through Cloudflare, which cuts connections idle >100 s — long prefills on
  big prompts exceed that before the first token. LAN clients bypass CF.
  Non-streaming requests cannot be kept alive this way (no bytes before the
  complete JSON) — Cloudflare's 100 s stays a hard wall for those.

### 2026-11-20 — OCR scan hardening pass (internal/proxy)

- Fixed 14 findings from an `ocr scan` review of the proxy package: nil-map panic on
  `stream_options: null`; non-stream responses now buffered before the status line is
  committed (mid-body upstream failure → 500, not a truncated 200); request >64 MiB →
  413 instead of silent truncation; oversized upstream response → 502; SSE line copy
  capped at 16 MiB (was unbounded); transport-level dial/TLS timeouts (still no
  overall client timeout — generations run for minutes); rightmost X-Forwarded-For
  entry; OpenAI-style error `type` per status; Anthropic SSE half-captured usage now
  falls back to estimation; `delta.reasoning_content` counted in streaming estimation;
  rune-based char counting; Responses SSE handles `response.incomplete` and missing
  usage; discovery probes get separate deadlines and `/health` body trusted only on 200.
- Deployment note: the NPM proxy for `llm.rantaeskola.fi` needs `proxy_read_timeout
  3600s` (+ `client_max_body_size 64m`, `proxy_buffering off`) — nginx's 90 s default
  killed long non-streaming generations (OCR sends 10+ min requests). Applied 2026-11-20.
