# Plan: Append-only audit log

- **Status:** complete (shipped 2026-11-25)
- **Owner:** maintainer
- **Started:** 2026-11-25
- **Issue:** user request (no Gitea ticket)

## Goal

An audit trail of everything that changes state or connects: user account
changes, server settings changes, backend changes, model changes, and
server↔server connections (spoke connect/disconnect, remote backend
connect/disconnect). Each entry records the time and the **actor's
username as a snapshot** — not the id — so renaming or deleting an account
cannot rewrite history. The store exposes **insert and read only**: there
is no update or delete path, at any layer.

## Non-goals

- No retention/purge (append-only forever; a home-scale write rate makes
  this irrelevant for years — revisit if it ever matters).
- No login/logout events (the ask is account *changes* + machine
  channels), no per-request logging.
- No API-key lifecycle events (create/revoke/delete): keys are not in the
  owner's category list, and revocation already has its own audit trail
  through the key's `revoked_at` timestamp.
- No redaction tooling or export formats — the read API + page are the
  interface.

## Design

**Table** (migration `0019_audit_log.sql`):

```sql
CREATE TABLE audit_log (
  id     INTEGER PRIMARY KEY AUTOINCREMENT,
  ts     TEXT NOT NULL,                -- UTC RFC3339
  actor  TEXT NOT NULL,                -- username snapshot, or "system"
  action TEXT NOT NULL,                -- "<category>.<verb>", e.g. backend.create
  target TEXT NOT NULL DEFAULT '',     -- human name of what changed
  detail TEXT NOT NULL DEFAULT ''      -- what changed (never secrets)
);
CREATE INDEX idx_audit_ts ON audit_log(ts DESC);
CREATE INDEX idx_audit_action ON audit_log(action);
```

**Store** (`internal/store/audit.go`): `InsertAudit(db, actor, action,
target, detail)` (stamps ts itself) and `QueryAudit(db, filter)` →
entries + total (category = action prefix, actor, free-text q, paging).
No other exported function touches the table.

**API write path**: `s.audit(c, action, target, detail)` resolves the
actor's username from the JWT claims at write time (one lookup; a vanished
user falls back to `user#<id>`) and inserts. Failures are logged, never
surfaced — an audit hiccup must not fail the mutation it records.

**API read path**: `GET /api/admin/audit?category=&actor=&q=&page=&page_size=`
(admin only) → `{entries, total, page, page_size}` newest-first. There is
no write, modify or delete endpoint.

**Instrumented events** (all after success):

| category | events |
|---|---|
| user | create, update (password/disabled/role/display/multiplier), self.update, self.password |
| settings | settings.update, federation.update (role + hub_url, never the token), tls.generate, tls.delete |
| backend | create, update, delete, models.add, remote.create, remote.rotate |
| model | update, benchmark, delete, group.create/update/delete |
| peer | create, rotate, update, delete (self + admin paths) |
| fed (actor=system) | peer.connect / peer.disconnect (hub side, incl. version), hub.connect / hub.disconnect (spoke side) |
| remote (actor=system) | backend.connect / backend.disconnect |

Connection events come from the live-channel seams that already exist:
`Manager.runPeerEvents` (hub online/offline per peer), `setSpokeConn` /
`clearSpokeConn` (spoke side), remote `Registry` register/unregister.

**Web**: admin **Audit log** page (`/admin/audit`): category select +
actor + free-text filters, table Time | Actor | Action | Target | Detail,
paging (50/page), refresh button. Sidebar entry under Admin.

## Decisions

- Actor is the **username snapshot** (owner requirement): renames and
  deletions never rewrite history; `system` for machine-channel events.
- Detail carries changed fields, never secrets (no tokens, no passwords,
  no API keys — names and settings values only).
- Append-only is enforced by API surface (no update/delete function
  exists), not by SQLite triggers — the DB file is operator-readable
  anyway, the guarantee is about the app.
